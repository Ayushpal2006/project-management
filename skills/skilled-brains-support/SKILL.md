# The Skilled Brains support

Work from the requested support threads, or from unread conversations in the brand support inbox when the user asks for an inbox sweep. The demonstrated mailbox is `support.theskilledbrains@gmail.com`. Select it by account identity in Gmail’s account switcher. Confirm the active account before drafting or sending. Use the current thread, the registered account email, and the course name as case inputs.

Use a connected Gmail tool when it has access to the correct mailbox and supports the operation. Otherwise use the signed-in browser through Computer Use in Codex or the available browser or computer-use integration in Claude. Use visible labels and roles as targets, and refresh the view after navigation. In Gmail, open the thread, read the latest request and relevant prior replies, and check the intended recipient. For website enquiry notifications, use the customer's address or Reply-To shown in the message and verify it before sending.

## Investigate the case

Use the signed-in Graphy admin dashboard at `www.theskilledbrains.com` when a case needs account or course evidence.

- **Missing certificate:** Open **Dashboard → Products → Courses**, choose the course and confirm its title on **Information**, then open **Certificates**. If multiple courses could match, check the customer’s enrollment before using the settings. Check **Certificate Issue Type** (Automatic on completion or Manual by admin). Check available completion and issuance evidence for the specific account. A course setting establishes how certificates are issued. Treat actual issuance as a separate fact to verify. If completion, issuance, or the course match is unclear, request the missing detail or flag the case for follow-up. Change settings or issue certificates only if the user explicitly requests that action.
- **Login or device access:** Open **Users → Learners**. Set **Search by** to **Email**, submit the registered email, and open the matching profile. Confirm the email on **Information** before touching any controls. Inspect **Unblock Learner on iOS** and **Login Details**, including **Last 3 Web Logins** and **Last 2 App Logins**. Use **Reset** to clear a previous search if needed. When explicitly authorized for this case, use **Unblock Learner** for an applicable iOS block or **Delete this device** on the affected login rows. Apply only the requested reset scope. After each change, re-read the profile and verify that the block state or target rows reflect the intended change. Check current state before retrying. If the account match or affected device is ambiguous, ask for the identifying detail before changing it.
- **General course or payment enquiry:** Read the original request and any prior offer. Use current official course information or an approved support policy for pricing, assistance, discounts, or other terms. If a decision is needed, flag it for the team and draft a reply that acknowledges the request without promising a decision.

## Reply and verify

Finish any authorized account action and verify its result before drafting a reply that describes it. Write a short, case-specific reply that answers the question, states only verified actions and findings, and gives the customer one clear next step. After a verified login reset, ask the customer to retry sign-in with their registered email. Avoid exposing internal account or device details in the reply.

Use the existing thread's **Reply**. Save the draft and verify **Draft saved** or the Gmail draft record. Send only when the user has explicitly authorized sending within the current batch or case scope. Verify the reply appears in the conversation or in Sent before marking it sent. If send status is uncertain, check the thread before retrying to avoid a duplicate. Report which cases were drafted, sent, or need a decision, and note any verified account changes.
